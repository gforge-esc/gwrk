### The one structural constraint worth knowing

`activatePhaseTests` (`src/engine/test-activator.ts:37-45`) matches a `@phase NN`
tag and then un-skips **every** `it.skip` in that file. Activation is therefore
file-scoped: one test file can carry exactly one phase.

The plan assigns two files to two phases each — `src/commands/adr.test.ts` is
created in phase 02 and **amended** in phase 08 (`--decide`), and
`src/commands/adr-dispatch.test.ts` is created in phase 03 and **amended** in
phase 11 (`--audit`). A whole-feature `define tests` run cannot express both
halves in one file:

- Tag the file with the earlier phase and the later phase's tests activate early,
  so phase 02's own `Done When` (`npx vitest run … src/commands/adr.test.ts`)
  fails on unimplemented phase-08 behaviour and the phase can never close.
- Tag it with the later phase and the earlier phase activates nothing, so
  `ACTIVATE_TESTS` establishes no RED for the work that phase is building.

Each file is therefore tagged with the phase that **first builds its subject**
and carries only that phase's cases. The later halves land when their phase runs
`gwrk define tests 029 --phase 08` / `--phase 11`, which appends `it.skip` blocks
plus the matching `@phase` tag to the already-active file — the activator handles
that correctly, because only the newly added skips remain to un-skip.

What that costs, precisely:

- **FR-023 is covered where the contract puts the logic.** `decide(record, today)`
  is an `adr-amend.ts` export (engine contract §5), so the status flip, the date
  stamp, the "changes only the Status and Date lines" invariant, and both
  refusals (already `Decided`, `Superseded`) are asserted in
  `src/engine/adr-amend.test.ts` — a phase-08 file the phase-08 gate already
  runs. Only the command-level halves ("dispatches no workflow", "regenerates the
  index after `--decide`") wait for the phase-08 amendment.
- **FR-027 / US-012 has no engine seam** — `--audit` is command wiring only — so
  it defers whole. Phase 11's gate runs `pnpm test:ci`, so the amendment is
  enforced there once written.

### Test-file naming divergence

The spec's acceptance scenarios cite `-t` filters against specific files, e.g.
`src/commands/adr.test.ts -t "FR-023: …"` and
`src/commands/adr-dispatch.test.ts -t "FR-027: …"`. Those two resolve only after
the phase-08 / phase-11 amendments above. Every other `-t` string in the spec
matches a test title in this run verbatim; no gate script uses `-t`, so no
`Done When` block is affected.

## Harness notes observed while writing these

- **Dynamic import, not a static one.** Each engine suite loads its module with
  `await import()` **inside** the test. A top-level static import of a
  not-yet-existing module fails at collection, and vitest then prints
  `Tests  no tests` — which `parseTestOutput` reads as `testsRun === 0`, the
  exact liveness condition `ACTIVATE_TESTS` and `TEST_GATE` NO-GO on. The
  dynamic form keeps every case a real, counted failure.
- **Fixture ids are assembled from parts.** FR-024 assertion 1 treats every bare
  `ADR-NNN` under `src/` as a citation that must resolve. The checker and parser
  suites need fixtures naming records that deliberately do not exist, so those
  ids are built with a helper (`adr("099")`) rather than written literally —
  otherwise `gwrk define adr --check` would fail on its own test files at
  phase 10.
- **`vi.restoreAllMocks()` also resets module mocks.** The grounding suite
  restores only its `process.stdout.write` spy; the blanket call reset the
  `resolveExtensionContext` mock and turned a fail-open assertion into a
  `TypeError` inside `agent.ts`.
- **A vacuous pass caught and fixed.** `runCli("define adr --help")` on a CLI
  without the subcommand falls back to the **parent** `define` help, which
  already carries an `Examples:` block — so the naive assertion passed before the
  feature existed. The test now pins the `Usage: … define adr` line first.
- `tsconfig.json` excludes `**/*.test.ts` and biome ignores most test globs, so
  neither gate would surface an error in these files (VR-005). All 14 were run
  locally, activated and skipped.

# Architecture context and assessment

Initialization installs project-owned design context without model calls. A separate assessment command produces evidence and ordered feature proposals. Blocked: none.

## Requirements

| Requirement | Acceptance |
|---|---|
| Deterministic setup | Fixed selections produce stable files |
| Existing projects | Source and accepted decisions remain intact |
| Re-init | Human edits survive with reported conflicts |
| Architecture selection | Explicit target composes with language and framework |
| Decision templates | Proposed records enter the configured corpus |
| Agent context | AGENTS.md, CLAUDE.md and GEMINI.md reference one context |
| Portable skill | Claude and Codex marketplace plus Gemini extension packaging |
| Assessment command | Shared workflow uses the configured definition agent |
| Assessment evidence | Findings cite source files and lines |
| Feature proposals | Dependencies order concrete changes and acceptance criteria |
| Self-assessment | Command runs against initialized gwrk and preserves the prior gap map |

## Boundaries

Domain functions resolve selections and render context from inputs. Filesystem adapters own persistence. The assessment command uses WorkflowRuntime. Model output proposes changes and cannot execute write intents.
